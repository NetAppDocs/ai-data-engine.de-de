= AI Data Engine Architektur
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine (AIDE) läuft auf der Infrastruktur, die Sie bereitstellen. Die Metadata Engine scannt Ihren Storage und erstellt einen durchsuchbaren Katalog. NetApp Console managt Ihr Deployment über einen Console Agent. Eine Model Context Protocol (MCP) Serveroption ermöglicht es KI-Clients, den Katalog innerhalb der von Ihnen festgelegten Grenzen zu durchsuchen.



[[components]]
== Komponenten

Das AI Data Engine Dashboard, die Untersuchung und die Richtlinien in NetApp Console basieren alle auf dem Metadatenkatalog. Die folgenden Komponenten erstellen den Katalog, verbinden ihn mit NetApp Console und ermöglichen den kontrollierten Zugriff für KI-Clients.



[[metadata-engine]]
=== Metadata Engine

Die Metadata Engine ist die Kernfunktion der AI Data Engine. Sie durchsucht die verbundenen Datenquellen, extrahiert Metadaten und speichert diese in einem durchsuchbaren Katalog. Sie liest oder klassifiziert keine Dateiinhalte. Die Metadata Engine aktualisiert den Katalog bei jedem Scanvorgang und erkennt dabei Hinzufügungen, Änderungen und Löschungen in Ihren Storage Systemen.



[[netapp-console-agent]]
=== NetApp Console-Agent

AI Data Engine erfordert einen in Ihrer Umgebung eingesetzten NetApp Console Agent. Der Console Agent ist eine allgemeine Plattformkomponente von NetApp, die die Verbindung zwischen Ihrer Umgebung und NetApp Console aufrechterhält. Er übernimmt die Authentifizierung und die Kommunikation zwischen NetApp Console und Ihrem AI Data Engine Deployment. Die Scan- und Katalog-Services werden in Ihrem AI Data Engine Deployment ausgeführt, nicht auf dem Console Agent.


NOTE: Der Console agent ist nicht spezifisch für AI Data Engine. Wenn Sie bereits einen Console agent für andere NetApp Services bereitgestellt haben, können Sie denselben Agenten verwenden. Anweisungen zum Deployment des Console agent finden Sie im link:https://docs.netapp.com/us-en/console-setup-admin/concept-agents.html["NetApp Console Agent-Dokumentation"].



[[governed-access-gateway]]
=== Gateway für kontrollierten Zugriff

Das Governed Access Gateway ist der MCP-Server für AI Data Engine. Es ermöglicht AI Clients die Suche im Metadatenkatalog. Das Gateway läuft in Ihrem AI Data Engine Deployment, und AI Clients verbinden sich über HTTPS aus Ihrem Unternehmensnetzwerk oder über VPN damit. Der Console Agent leitet keinen MCP-Datenverkehr weiter.

Microsoft Entra ID authentifiziert Benutzer, und das Gateway beschränkt jeden KI-Client auf die Sammlungen, deren Suche der Benutzer autorisiert ist. Das Gateway unterstützt nur Metadatensuche und Verschlagwortung, und nur fortgeschrittene Benutzer können Dateien verschlagworten. Es ruft keine Dateiinhalte ab.

link:../mcp/learn-about-mcp.html["Weitere Informationen zum Governance-gesteuerten KI-Zugriff"].



[[deployment-types]]
== Bereitstellungsarten

AI Data Engine unterstützt zwei Deployment-Typen. Beide führen AI Data Engine Services auf Kubernetes aus.

AIDE Einzelknoten-Deployment:: Läuft auf einer einzelnen, von Ihnen bereitgestellten Linux VM. Das Installationsprogramm stellt k3s und die zugehörigen Komponenten automatisch bereit. Ein Einzelknoten Deployment bietet keine Hochverfügbarkeit oder horizontale Skalierung.
AIDE Multi-Node Deployment:: Läuft auf einem von Ihnen bereitgestellten Kubernetes Cluster und ist für größere Umgebungen gedacht, die eine hohe Verfügbarkeit erfordern.


Informationen zu unterstützten Plattformen, Dimensionierung und Infrastrukturanforderungen finden Sie unter link:../deploy/aide-requirements.html["AIDE-Anforderungen"].

Für jeden Bereitstellungstyp gibt es außerdem ein separates Verfahren für Umgebungen, die das Internet nur über einen ausgehenden Proxy erreichen. Weitere Informationen finden Sie unter link:../deploy/configure-proxy.html["Informationen zu Proxys für AI Data Engine"].

link:../deploy/deployment-overview.html["Weitere Informationen zu den Bereitstellungsoptionen"].



[[data-flow]]
== Datenfluss

AI Data Engine nutzt zwei separate Pfade: einen, der den Katalog erstellt und ihn für NetApp Console bereitstellt, und einen, der AI Clients bedient.



[[metadata-scanning-and-netapp-console-access]]
=== Metadatenscanning und Zugriff auf die NetApp Console

. AI Data Engine wird auf einer von Ihnen gemanagten Infrastruktur eingesetzt und mit einem NetApp Console Agent verbunden.
. Sie verbinden die Datenquellen, die AI Data Engine unter *Datenquellen* katalogisieren soll. Weitere Informationen finden Sie unter link:../data-sources/connect-data-source.html["Herstellen einer Verbindung mit einer Datenquelle"].
. Die Metadata Engine durchsucht die Datenquellen, um Metadaten zu extrahieren und diese im Katalog zu indizieren.
. In NetApp Console zeigt das Dashboard Storage Einblicke aus dem Katalog an, und Investigation ermöglicht direkte Abfragen des Katalogs mit Metadatenfiltern.
. Sie können Suchkriterien als Richtlinien speichern und diese erneut ausführen, um übereinstimmende Dateien zu identifizieren, und Sie können in Investigation Aktionen für Dateien ausführen.



NOTE: Der Katalog spiegelt die während des Scans erfassten Metadaten wider. Änderungen an den Quelldateien werden im Katalog angezeigt, nachdem die betroffenen Dateien und Verzeichnisse erneut gescannt und die Ergebnisse indiziert wurden.



[[governed-ai-access]]
=== KI-Zugriff mit Governance

. Sie konfigurieren Microsoft Entra ID, aktivieren Sammlungen für den AI-Zugriff und wählen aus, welche Benutzer die einzelnen Sammlungen durchsuchen dürfen.
. Ein Benutzer verbindet einen KI-Client mit dem HTTPS-Endpunkt des Governed Access Gateway und meldet sich mit Microsoft Entra ID an.
. Das Gateway überprüft die Zugriffsberechtigung des Benutzers und leitet autorisierte Anfragen an die Metadata Engine weiter.
. Der AI Client durchsucht die Metadaten in den Sammlungen, auf die der Benutzer zugreifen kann und für die er Aktionen ausführen kann.
